# go-agent 项目结构优化设计文档

> 目标：在不改变现有功能的前提下，理清模块边界、明确职责、消除重复与隐式全局状态，使项目结构更清晰、可测试、易演进。
>
> 原则：**渐进式、可回退、每步编译通过且测试绿**。本次以「结构重组 + 去重」为主，不做功能增强。

---

## 一、现状概览

- module：`nano_cc`，Go 1.26.1
- 入口：根目录 `main.go` → `internal/web/app.NewServer().Run()`
- 总量：约 10,358 行 Go（含测试），最大集中在 `internal/web/runtime`（约 1500 行业务 + 2000 行测试）

当前目录（简化）：

```
go-agent/
├── main.go
├── cmd/                      # 空目录（遗留）
└── internal/
    ├── assistant/            # 系统提示词构建
    ├── config/               # 配置加载 + LLM 客户端 + 全局 Client（职责过载）
    ├── logger/               # 日志（全局单例）
    ├── safety/               # 路径越界校验
    ├── sessions/             # 技能加载/合并/渲染
    ├── tools/                # 工具定义 + handler（runtime 无关）
    └── web/
        ├── app/              # HTTP 层
        ├── auth/             # 鉴权
        ├── runtime/          # agent 主循环 + 工具编排 + 上下文压缩（过大）
        │   └── hooks/        # 生命周期钩子
        └── storage/          # MySQL + Redis 持久化
```

依赖方向总体健康（底层包不反向依赖上层，无循环依赖）。问题主要在**职责过载、边界模糊、重复实现、隐式全局状态**。

## 二、问题清单（按严重度）

### A. 边界不清 / 职责过载

| 编号 | 问题 | 说明 |
|---|---|---|
| A1 | `config` 包职责过载 | `client.go`(156 行) 是完整的 DeepSeek HTTP/SSE 客户端，与「配置加载」无关；且持有全局可变变量 `Client`/`ModelID`，隐式全局状态，难测试 |
| A2 | 工具层职责分散 | `tools` 定义 schema+handler，但 `runtime` 又有 `tool_catalog`(查表/白名单)、`tool_registry`(分发)、`tool_execution`(执行)。分发逻辑被劈成「handler map + 3 处 if-name 特判」（`todo_write`、`spawn_subagent`、`read_persisted_output`），不一致 |
| A3 | `runtime` 包过大 | 上下文压缩相关 7 个文件已成独立子系统（compression / tool_result / message_window / recent_retention / full_history / summarizer / token_estimator），与对话循环、工具、子 agent 平铺在同一包 |
| A4 | `cmd/` 空目录 + 根 `main.go` | 违反 Go 项目惯例 |

### B. 重复代码

| 编号 | 问题 | 位置 |
|---|---|---|
| B1 | ID 生成 4 套实现、风格各异 | `app/ids.go`(时间戳,有碰撞风险)、`runtime/ids.go`、`runtime/hooks/ids.go`、`auth/service.go` |
| B2 | `toolResultPreview` 重复 3 处 | `app/conversation_handlers.go`、`runtime/hooks/tool.go`（实现略有差异） |
| B3 | `truncate` 重复 | `runtime/helpers.go`、`hooks/tool_audit.go` |
| B4 | tool_result JSON 解析重复 | `app/conversation_handlers.go:parseToolMessageContent`、`runtime/tool_result_compression.go:parseToolResult` |
| B5 | 路径越界校验逻辑重复 ≥4 处 | `safety.SafePathFromRoot`、`tools/path_guard.go`、`runtime/subagent.go`、`hooks/tool_audit.go` 各自实现 clean+HasPrefix |
| B6 | `todo_write` 同名文件两处 | `tools/todo_write.go`(执行) vs `runtime/todo_write.go`(提醒)，职责不同但同名易误导 |

### C. 一致性 / 维护性

| 编号 | 问题 | 说明 |
|---|---|---|
| C1 | 隐式全局状态 | `logger` 全局单例 + `config.Client` 全局；`summarizer.go` 直接引用 `config.Client`，绕过 Service 注入，与 `Service.Cfg.LLM` 注入方式不一致 |
| C2 | 消息存储新旧两套并存 | `models.go` 注释 `Message` 表「已不使用」，实际以 `Conversation.HistoryJSON` 整块 JSON 存；但 `messages_repo.go` 仍保留 `CreateMessage`/`ListMessagesByConversation`，疑似死代码 |
| C3 | 硬编码默认凭据 | `config/env.go`、`web_config.go` 中 MySQL/Redis host、密码硬编码 |
| C4 | 无效签名 | `tools/definitions.go:strParam(desc, required)` 的 `required` 参数未被使用 |
| C5 | 接口分散定义 | `app.serverStore` 与 `runtime.conversationStore` 各自对 `*storage.Store` 抽象，演进需同步两份 |

## 三、优化目标结构

```
go-agent/
├── cmd/server/main.go         # 入口迁移至此（或保留根 main.go，二选一）
└── internal/
    ├── idgen/                 # 【新】统一 ID 生成（消除 B1）
    ├── llm/                   # 【新】LLM 客户端，从 config 抽出（A1/C1）
    ├── assistant/
    ├── config/                # 仅保留配置加载/路径/布局（瘦身）
    ├── logger/
    ├── safety/                # 成为唯一路径越界校验入口（B5）
    ├── sessions/
    ├── tools/                 # 工具唯一权威：定义 + 分发 + 白名单（A2）
    └── web/
        ├── app/
        ├── auth/
        ├── runtime/
        │   ├── compression/   # 【新】上下文压缩子系统（A3）
        │   ├── hooks/
        │   └── shared/        # 或复用 tools/idgen，去重 B2/B3/B4
        └── storage/
```

### 职责边界（目标态）

- **idgen**：所有随机/唯一 ID 的唯一来源，统一格式与碰撞规避。
- **llm**：DeepSeek/OpenAI 兼容客户端实现，通过依赖注入提供给 `runtime.Service`，不再有包级全局 `Client`。
- **config**：只做「读取配置 + 路径解析 + 布局校验」，产出 `Config` 值对象。
- **safety**：所有「路径是否越界 workspace root」的判断统一走此包。
- **tools**：工具的「定义 schema + 分发执行 + 白名单」唯一权威；消除 if-name 特判，全部进 handler 注册表。
- **runtime**：只做编排（对话主循环、工具调用编排、子 agent、SSE）；压缩逻辑下沉到 `runtime/compression`。

## 四、实施计划（分阶段，每阶段独立可验证）

> 验证标准：每阶段结束 `go build ./...` 通过 + `go test ./...` 通过。

### 阶段 0：基线
- 运行 `go build ./...` 与 `go test ./...`，记录当前通过状态作为回归基线。

### 阶段 1：低风险去重（B1/B2/B3/B4）
1. 新建 `internal/idgen`，统一 ID 生成；逐个替换 `app`/`runtime`/`hooks`/`auth` 中的 `newID`/`randomHexID`/`randomID`（注意 auth 的 ID 语义是否需保持 hmac 形式，若是则保留并标注）。
2. 抽公共 `toolResultPreview`、`truncate`、tool_result JSON 解析到一处（建议 `tools` 或新 `runtime/shared`），替换重复点。

### 阶段 2：拆分 LLM 客户端（A1/C1）
1. 新建 `internal/llm`，迁移 `config/client.go` 的 deepseekClient。
2. 移除 `config` 包级全局 `Client`/`ModelID`，改由 `app.NewServer` 构造 `llm.Client` 并注入 `runtime.NewService`。
3. 修正 `summarizer.go` 改用注入的 client，不再引用全局。

### 阶段 3：统一工具层（A2）
1. 将 `todo_write`、`spawn_subagent`、`read_persisted_output` 统一注册进 `tools.Handlers`（或 runtime 的统一注册表），消除 `tool_registry`/`tool_execution` 中的 if-name 特判。
2. 明确 `tools`（定义+执行）与 `runtime`（编排）的边界；`tool_catalog` 仅保留白名单过滤。
3. `runtime/todo_write.go` 改名为 `todo_reminder.go`（B6）。

### 阶段 4：压缩子系统下沉（A3）
1. 新建 `internal/web/runtime/compression`，迁移 7 个压缩相关文件及其测试。
2. 通过最小公开接口暴露给 `runtime`，调整 import。

### 阶段 5：路径校验归一（B5）
1. 让 `tools/path_guard.go`、`runtime/subagent.go`、`hooks/tool_audit.go` 的越界判断统一调用 `safety` 包。

### 阶段 6：清理与收尾（A4/C2/C3/C4/C5）
1. 处理 `cmd/`：迁移 `main.go` 到 `cmd/server/` 或删除空目录（**待你决策**）。
2. 确认 `messages` 表新旧存储路径，删除确认无用的死代码（**需你确认 C2**）。
3. 外移硬编码凭据为环境变量/配置（**待你决策范围**）。
4. 修正 `strParam` 无效参数。
5. 评估是否合并 `serverStore`/`conversationStore` 接口。

## 六、风险与回退

- 每阶段独立提交，可单独回退。
- 重构不改变外部 HTTP API 与持久化 schema，对前端与数据库无影响。
- 主要风险点：阶段 2（全局 Client → 注入）与阶段 3（工具分发统一），涉及调用链改动较多，需重点回归 `runtime` 测试。
