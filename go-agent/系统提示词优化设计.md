# 系统提示词优化设计文档

> 目标：参考 Claude Code 的系统提示词设计理念，结合 nano_cc 项目实际（Go + Web 浏览器对话 + Skill/Subagent/Memory 运行时），将现有"Markdown 分节"提示词，重构为**语义化标签 + 行为准则**的结构化提示词。
> 本文档供审阅，确认后再改代码。

---

## 1. 现状梳理

### 1.1 提示词组装链路

```
system_prompt.md  ──load──►  Service.BasePrompt
                                     │
runtime.buildSystemPrompt(ctx, conversation, user, snapshot)
   ├─ 收集 ToolNames（来自 Tools.Definitions）
   ├─ 取 SkillDescriptions（loader.GetDescriptions → <skills> XML）
   ├─ 组 MemorySection（用户档案卡 + 近期话题）
   └─ assistant.BuildSystemPrompt(PromptOptions{...})
                                     │
                          最终 system 消息字符串
```

涉及文件：
- `system_prompt.md`：身份基底文本（4 句话，偏笼统）。
- `internal/assistant/prompt.go`：`BuildSystemPrompt` 真正拼装结构。
- `internal/web/runtime/prompt_builder.go`：注入运行时上下文（surface / 工作目录 / 工具名 / 技能 / 记忆）。
- `internal/web/runtime/subagent.go`：子 agent 追加"Child Agent Context"。

### 1.2 现有结构（输出形态）

```
# System Instructions
## Identity            ← BasePrompt 原文
---
## Runtime Context     ← Surface / Workspace root
---
## Runtime Tools       ← 工具名清单 + persisted-output 指引
---
## Skills              ← <skills> 摘要 + 加载规则
---
## Memory              ← 用户档案卡 + 近期话题
```

### 1.3 现存问题

1. **身份描述笼统**：`system_prompt.md` 只说"通用 agent"，缺少语气、主动性、约定遵循、安全边界、任务执行方法论等 Claude Code 式的行为准则。
2. **分节标签语义弱**：用户期望 `<identity>` / `<tools>` / `<skills>` / `<workspace>` / `<memory>` 这类语义标签（与技能已用的 `<skills>` XML 风格一致），而非 `## Runtime Context` 这类运行时实现术语。
3. **"Runtime Context"与"Workspace"混在一起**：surface 与工作目录耦合，缺少独立的 `<workspace>` 概念。
4. **缺少通用 agent 行为规范**：无简洁性、最小改动、工具优先级、并行工具调用、安全确认等准则。

---

## 2. 设计目标

1. 采用**语义化标签**组织提示词：`<identity>`、`<tools>`、`<skills>`、`<workspace>`、`<memory>`，外层包裹运行时环境信息。
2. `system_prompt.md` 升级为**完整的身份 + 行为准则**文本（Claude Code 风格：语气、主动性、遵循约定、任务方法、安全），但保持精炼、与项目能力匹配（不臆造不存在的能力）。
3. 保持**运行时动态注入不变**：工具名、技能摘要、工作目录、记忆仍由 `prompt_builder.go` 动态填充，仅改变"渲染外壳"。
4. **向后兼容**：`BasePrompt` 为空时回退到内置默认；`ToolNames`/`Skills`/`Memory` 为空时对应标签不输出。
5. **subagent 复用**：子 agent 提示词继续在主结构后追加 `<subagent>` 段。

---

## 3. 目标提示词结构

最终 system 消息形态（标签化）：

```
<identity>
  （来自 system_prompt.md 的身份 + 行为准则全文）
</identity>

<workspace>
  Surface: the browser chat experience for user <username>
  Working directory: <WorkspaceRoot>
  - 所有运行时文件/Shell 操作默认以此为根目录……
</workspace>

<tools>
  本次会话可用工具：
  - bash
  - read_file
  ...
  （含 read_persisted_output 时追加分块读取指引）
</tools>

<skills>
  以下技能仅提供摘要；使用前必须用 load_skill 加载完整说明：
  <skills>...XML...</skills>   ← 复用 GetDescriptions 原始内容
  规则：……
</skills>

<memory>
  ### 用户档案卡 ……
  ### 近期聊过的话题 ……
</memory>
```

> 说明：`<skills>` 外层为语义分节标签，内层是 `GetDescriptions()` 已产出的 `<skills>` XML，二者层级清晰，不冲突。

排序理由：身份 → 环境（我在哪）→ 能力（我能用什么）→ 技能（专项流程）→ 记忆（关于用户）。与 Claude Code "先定义角色，再给环境与工具，最后给上下文"的层次一致。

## 4. 具体改动方案

### 4.1 `system_prompt.md`（重写身份 + 行为准则）

新内容大纲（中英按当前默认语言走英文，与现有 `DefaultBaseSystemPrompt` 保持一致，正文精炼）：

- **角色定位**：nano_cc，运行在浏览器对话场景的通用型 agent；能做问答、分析、规划、写作、编码、文件检查与端到端任务执行。
- **语气与风格**：直接、简洁、有用；先给答案/行动，少寒暄；引用代码用 `file:line`。
- **主动性**：被要求做事时把事做完；但不过度扩张范围（呼应"do what's asked, nothing more"）。
- **遵循约定**：编辑前先读；模仿既有代码风格与工程惯例；最小化改动。
- **任务方法**：多步任务先简要计划（可配合 `todo_write`）；复杂检索/隔离任务可用 `spawn_subagent`。
- **工具使用**：优先用工具完成而非猜测；能并行的工具调用并行发起；不要假设有 shell/文件能力，除非运行时已提供（由 `<tools>`/`<workspace>` 体现）。
- **安全边界**：危险/不可逆操作（删除、越界路径、覆盖未提交改动等）需谨慎，遵守运行时限制。

保持约 1 屏内，避免冗长。

### 4.2 `internal/assistant/prompt.go`（渲染外壳标签化）

核心改动：`BuildSystemPrompt` 由"`## 分节` + `---` 分隔"改为"语义标签包裹"。

- 新增内部 helper：`renderTag(tag, body string) string` —— 输出 `<tag>\n{body}\n</tag>`，body 为空则跳过该标签。
- 段落映射：
  - `Identity`  → `<identity>`（BasePrompt / 默认）
  - 新增 `<workspace>`：合并 Surface + Working directory（原 Runtime Context 拆分）
  - `Runtime Tools` → `<tools>`
  - `Skills` → `<skills>`
  - `Memory` → `<memory>`
- 段间用空行分隔（去掉 `---`，标签已具备边界语义）。
- `PromptOptions` 字段保持不变（无需改调用方签名）。
- 保留：工具为空不输出 `<tools>`；技能为空不输出 `<skills>`；记忆为空不输出 `<memory>`；`read_persisted_output` 指引逻辑不变。

> 兼容性提示：现有 `prompt_test.go` 断言了 `# System Instructions` / `## Identity` / `---` 等旧文案，需同步更新为新标签断言（见 4.5）。

### 4.3 `internal/web/runtime/prompt_builder.go`

- 基本不变。`Surface` 与 `WorkingDirectory` 仍按现状传入；标签化由 `BuildSystemPrompt` 内部完成。
- 可选微调：无需改动逻辑，仅依赖渲染层变化。

### 4.4 `internal/web/runtime/subagent.go`

- `buildSubagentSystemPrompt` 追加段由 `---\n\n## Child Agent Context` 改为 `\n\n<subagent>\n...\n</subagent>`，与新风格统一。内容（不可见父历史 / 仅用当前任务与工作区 / 不可再 spawn / 仅输出摘要）保持不变。

### 4.5 测试同步

- `internal/assistant/prompt_test.go`：更新断言为 `<identity>`、`<workspace>`、`<tools>`、`<skills>`、`<memory>` 标签及其内部关键文案；移除对 `# System Instructions` / `---` 的断言。
- `internal/web/runtime/runtime_test.go`（第 ~1013 行 `TestBuildSystemPrompt_DoesNotRequireToolRegistry`）：若断言了旧文案需同步；否则仅验证不 panic，保持。
- `workspace/system_prompt.md`：是运行期工作副本，**保持同步更新**为新身份文本（确认是否需要一并改，见"待确认"）。

## 5. 影响面 & 风险

| 项 | 说明 |
|---|---|
| 调用方签名 | `PromptOptions` 不变，`BuildSystemPrompt` 签名不变，调用方零改动 |
| 行为变化 | 仅 system 提示词文本结构变化；工具/技能/记忆注入逻辑不变 |
| 测试 | 需更新 2 个测试文件的字符串断言 |
| 模型兼容 | 标签化对当前模型（deepseek）友好，XML 风格与已有 `<skills>` 一致 |
| 回退 | BasePrompt 为空仍回退内置默认（默认文本也同步更新） |

## 6. 已确认决策

1. **语言**：`system_prompt.md` 正文用**中文**编写身份与行为准则；记忆区保持中文。`DefaultBaseSystemPrompt` 同步改为中文。
2. **workspace 副本**：只更新根目录 `go-agent/system_prompt.md`，**不动** `workspace/system_prompt.md`。
3. **产品背景**：`<identity>` 中写入 **nano_cc 的简要背景**（浏览器对话式通用 agent 平台），再描述角色与能力。
