# go-agent TUI 本地化与 Web/DB/Redis 清理设计文档

## 1. 背景与目标

当前 go-agent 已迁移到 TUI 形态，本次设计目标是在不破坏现有 TUI 能力的前提下，移除 Web 时代遗留的 HTTP、数据库、Redis、ES 等服务端操作代码；若某些 Web/DB 能力仍承载有效功能，则先迁移到本地文件或本地内存结构，再清理旧代码。

本设计仅给出清理与迁移方案，不执行代码删除。待用户审阅通过后，再进入实现阶段。

## 2. 当前项目核查结论

### 2.1 TUI 主链路已经使用本地 Store

TUI 启动链路为 `main -> cli -> local.Bootstrap -> runtime.Service`。`local.Bootstrap` 加载本地配置、`.link` skills、workspace MCP 配置，并创建本地 Store：`internal/local/bootstrap.go:34`、`internal/local/bootstrap.go:52`、`internal/local/bootstrap.go:67`、`internal/local/bootstrap.go:77`、`internal/local/bootstrap.go:78`、`internal/local/bootstrap.go:84`。

本地 Store 是 `sync.RWMutex + map + 文件存储` 组合，核心字段包括 conversations、messages、persisted outputs、context summaries、model history、memory store、session history 和 locks：`internal/local/store.go:15`。本地锁已用 map 实现：`internal/local/store.go:449`、`internal/local/store.go:473`、`internal/local/store.go:482`。

### 2.2 Web 包已删除，但 DB/Redis/ES 代码仍存在

当前已有架构测试禁止 `internal/web` 目录和 import 回流：`architecture_test.go:10`、`architecture_test.go:24`。核查文件系统也未发现 `internal/web` 目录。

但旧 DB Store 仍保留 MySQL、Redis、ES 初始化与健康检查：`internal/agent/storage/store.go:17`、`internal/agent/storage/store.go:29`、`internal/agent/storage/store.go:38`、`internal/agent/storage/store.go:44`、`internal/agent/storage/store.go:56`。配置与依赖也仍保留：`internal/config/config.go:28`、`internal/config/config.go:45`、`config.json:13`、`config.json:17`、`go.mod:6`、`go.mod:7`、`go.mod:11`。

## 3. 五类功能迁移状态

### 3.1 记忆功能

**结论：TUI 主链路已迁移到本地 Markdown；DB 版记忆仓储仍是残留。**

本地长期记忆使用 workspace 下的 `memory/` 目录和 `memory/memory.md` 索引。`MarkdownMemoryStore` 负责布局、读写、替换、裁剪和会话记忆文件：`internal/local/memory_store.go:21`、`internal/local/memory_store.go:29`、`internal/local/memory_store.go:46`、`internal/local/memory_store.go:64`、`internal/local/memory_store.go:108`、`internal/local/memory_store.go:132`、`internal/local/memory_store.go:140`、`internal/local/memory_store.go:155`。

本地 Store 已把 runtime 记忆接口转发到 Markdown 存储：`internal/local/store.go:261`、`internal/local/store.go:290`、`internal/local/store.go:321`、`internal/local/store.go:334`、`internal/local/store.go:346`。runtime 的记忆接口仍是抽象 Store，不直接依赖 DB：`internal/agent/runtime/runtime.go:34`。

需要清理的残留包括 DB 版 `memories`、`conversation_memories` repo 与相关 migration。注意不能直接删除 `internal/agent/storage/models.go` 中的共享模型，因为 runtime/local/mcp 仍复用 storage 模型。

### 3.2 上下文压缩功能

**结论：压缩主链路已在本地执行；context summary 按最新要求无需存储，继续作为进程内缓存即可。**

压缩策略通过 `compression.Store` 抽象访问存储：`internal/agent/runtime/compression/compression.go:44`。runtime 每轮 LLM 前执行 request-only 压缩：`internal/agent/runtime/context_compression.go:30`，上下文溢出时执行 reactive compact：`internal/agent/runtime/context_compression.go:62`。

大工具结果已本地文件落盘并支持按 id 读取：`internal/local/store.go:185`、`internal/local/store.go:207`、`internal/local/persisted_output_files.go:35`、`internal/local/persisted_output_files.go:139`。模型历史也已本地保存：`internal/local/store.go:357`、`internal/local/store.go:379`。

`ContextSummary` 目前只写 `summaries` map：`internal/local/store.go:244`、`internal/local/store.go:251`；这符合“context summary 无需存储”的要求。仍需补齐的是 persisted output 的 hash 去重索引：当前只查内存 map：`internal/local/store.go:234`，重启后可能重复落盘，但不影响已有 marker id 读取。

### 3.3 历史会话与模型历史会话

**结论：已迁移到本地文件。**

本地会话目录为 `$HOME/link/session`：`internal/config/local_config.go:92`。`SessionHistoryStore` 负责保存普通 display history 和 model history：`internal/local/session_history_store.go:19`、`internal/local/session_history_store.go:46`、`internal/local/session_history_store.go:54`、`internal/local/session_history_store.go:62`、`internal/local/session_history_store.go:107`、`internal/local/session_history_store.go:165`。

本地 Store 在写 history/model history 时落文件，并支持 `/resume` 恢复：`internal/local/store.go:121`、`internal/local/store.go:147`、`internal/local/store.go:357`、`internal/local/store.go:379`、`internal/local/store.go:393`、`internal/local/store.go:400`。

可清理的残留包括 DB 版 conversations/messages/model histories repo、Redis conversation cache、DB session repo 等。

### 3.4 Skills 功能

**结论：TUI 本地 skills 已可用；runtime 仍保留 DB skill 兼容接口和测试语义，应迁移后清理。**

本地启动读取用户级 `~/.link/skills` 和 workspace 级 `<cwd>/.link/skills`：`internal/local/bootstrap.go:48`、`internal/local/bootstrap.go:52`、`internal/config/local_config.go:84`、`internal/config/local_config.go:108`。Skill loader 支持扫描 `SKILL.md/skill.md`、合并与 workspace 覆盖 user：`internal/sessions/skill.go:62`、`internal/sessions/skill.go:106`、`internal/sessions/skill.go:110`、`internal/sessions/skill.go:123`。

不足点：runtime Store 接口仍要求 `ListEnabledSkillsByUser`：`internal/agent/runtime/runtime.go:22`；每轮仍先从 Store 构造 DB skill loader，再合并本地 loader：`internal/agent/runtime/prompt_builder.go:56`、`internal/agent/runtime/prompt_builder.go:60`、`internal/agent/runtime/prompt_builder.go:68`。本地 Store 目前只是返回空：`internal/local/store.go:67`。工具描述也仍写“database skills”：`internal/tools/definitions.go:75`。

因此需要先把 runtime skill snapshot 改成纯本地 SkillProvider/SkillLoader，再删除 DB skill repo、`storage.Skill` 相关接口与旧测试。

### 3.5 MCP 功能

**结论：workspace MCP 已迁移到本地配置；用户 DB MCP 兼容路径仍是残留。**

本地 MCP 配置路径为 `<cwd>/.link/.mcp.json`：`internal/config/local_config.go:116`，启动时读取并注入 manager：`internal/local/bootstrap.go:77`、`internal/local/bootstrap.go:78`、`internal/local/bootstrap.go:83`、`internal/local/bootstrap.go:91`。配置解析支持 `mcp_servers` 数组和 `mcpServers` map，且支持 stdio/sse/streamable：`internal/agent/mcp/config.go:120`、`internal/agent/mcp/config.go:155`、`internal/agent/mcp/config.go:181`、`internal/agent/mcp/config.go:194`。

不足点：`mcp.Manager` 仍保留 `Store` 接口和 `EnsureUserSessions`，会尝试从 Store 拉取用户 MCP：`internal/agent/mcp/manager.go:27`、`internal/agent/mcp/manager.go:220`、`internal/agent/mcp/manager.go:223`。本地 Store 返回空：`internal/local/store.go:63`。如果未来只保留 workspace MCP，应删除 user DB MCP 路径，并同步调整 `tool_registry` 中对 user session 的调用。

## 4. 推荐实施方案

### 4.1 总体策略

推荐采用“先补齐本地存储缺口，再删除 DB/Web 残留”的两阶段方案：

1. **保护当前 TUI 主链路**：保留 `internal/local`、`internal/agent/runtime`、`internal/agent/mcp` workspace 路径、`internal/sessions`、`internal/tools`。
2. **补齐仍有功能价值但未完全落本地的点**：persisted output hash 索引跨重启恢复、runtime skills/MCP 去 DB 接口化；context summary 明确不做文件持久化。
3. **清理旧服务端仓储**：删除 DB/Redis/ES Store、repo、migration、配置项与依赖。
4. **增加架构防回归测试**：除 `internal/web` 外，增加禁止 MySQL/Redis/ES 依赖回流、禁止 DB repo 回流的测试。

### 4.2 本地存储设计

- 记忆：继续使用 workspace `memory/` 和 `memory/sessions/`。不新增数据库替代层。
- 历史会话：继续使用 `$HOME/link/session/<session_id>/history` 和 `model_history`。
- 上下文压缩：`ContextSummary` 继续作为进程内 map 缓存，不落盘；大工具结果和模型历史仍走本地文件存储。
- persisted output：保留 `task_outputs/tool-results`，在 `GetPersistedOutputByMessageHash` miss 时按当前 session 扫描 metadata 并回填内存 hash index，避免重启后重复落盘。
- locks：继续使用 `local.Store.locks map[string]string`，不引入文件锁；TUI 单进程场景足够。

### 4.3 Skills 去 DB 方案

将 `runtime.Service` 的 skill 来源从 `Store.ListEnabledSkillsByUser` 改为本地 `*sessions.SkillLoader` 或轻量 `SkillProvider`：

1. `local.Bootstrap` 继续加载 user/workspace skills。
2. `buildSkillSnapshot` 不再访问 Store，直接基于本地 loader 构造 snapshot。
3. 删除 `buildDBSkillLoader` 和 DB skill fallback 文案。
4. 删除 `storage.Skill`、`skills_repo.go`、skills migration 前，先迁移或删除依赖 DB skill 的单测。

### 4.4 MCP 去 DB 方案

将 MCP manager 简化为 builtin/workspace 两类本地配置，当前 TUI 主要使用 workspace：

1. 删除 `mcp.Store` 接口和 `EnsureUserSessions`，或至少先将其标记为 legacy 并从 runtime 调用链移除。
2. `ToolsForUser` 改为返回 builtin + workspace 工具，`userID` 仅保留兼容参数或移除。
3. 删除 `storage/mcp_repo.go` 和 `mcp_servers` migration 前，确认没有 CLI 命令依赖 DB CRUD。

### 4.5 Storage 包拆分策略

不要直接删除整个 `internal/agent/storage` 包。当前 `storage.Message`、`storage.Conversation`、`storage.MCPServer`、`storage.Memory` 等模型仍被 runtime/local/mcp/tui 复用。

建议先拆分：

- 保留或重命名纯模型/序列化：`models.go`、`conversation_history.go`。
- 删除 DB 实现文件：`store.go`、`cache.go`、`lock.go`、各 repo、migrations、scan/es repo。
- 若为减少改动，可第一阶段保留包名 `storage`，只删除 DB 文件；第二阶段再考虑改名为 `model` 或 `domain`。

### 7.2 新增/调整测试

## 8. 风险与规避

1. **误删共享模型风险**：`internal/agent/storage` 不能整体删除，先保留模型文件。
2. **DB skill 测试失败风险**：先改 runtime skill snapshot，再删除旧测试或迁移为本地 skills 测试。
3. **MCP user session 清理风险**：确认没有 CLI/API 仍使用用户 DB MCP；当前 TUI workspace MCP 不受影响。
4. **压缩缓存行为变化**：context summary 不落盘，重启后不会复用摘要缓存；这是明确接受的行为。
5. **配置字段删除影响**：先删除代码引用，再清理 config/go.mod，避免编译失败。

## 9. 建议执行顺序

1. 保持 context summary 内存缓存不变，补齐 persisted output hash 的本地恢复缺口。
2. 改造 runtime skills：移除 DB skill snapshot 依赖，更新 load_skill 文案和测试。
3. 改造 MCP manager/runtime：移除 user DB MCP 调用链，仅保留 workspace/builtin 本地能力。
4. 删除 DB/Redis/ES repo、migration、旧 store/cache/lock。
5. 清理 config.json、config.go、env.go、go.mod/go.sum。
6. 增加架构防回归测试并运行全量测试。
