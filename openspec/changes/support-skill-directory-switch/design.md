## Context

当前技能加载流程会在 `load_skill` 时返回技能正文和 runtime 路径提示，但不会把技能来源目录写入后续工具执行上下文。现有 Web runtime 只向工具 handler 注入统一的 `WorkspaceRoot`、`CommandBinDir`、`CommandScriptDir`，并默认让 bash / 文件工具都在 workspace 根目录下执行。这样虽然满足了统一边界控制，却让磁盘上的技能无法通过相对路径访问自身目录中的脚本、配置或资源文件。

这次变更横跨 skill 装配、runtime 工具上下文和工具默认 cwd 选择逻辑，适合先明确技能目录来源、切换条件和回退规则，再进入实现。

## Goals / Non-Goals

**Goals:**
- 让文件系统中的技能在被执行后，后续工具调用能够自动以该技能目录作为默认 cwd。
- 保持现有 workspace 边界校验，避免因为技能目录切换而放宽越权访问范围。
- 对没有本地目录的技能来源（例如 DB skill）保持兼容，继续回退到当前 workspace 根目录。
- 让测试和审计能够区分“普通 workspace 执行”和“技能目录执行”。

**Non-Goals:**
- 不引入会话级持久化 cwd，也不支持模型任意在多个技能目录之间显式切换。
- 不改变 skill 管理方式，不新增技能打包格式或 manifest。
- 不放宽当前工具授权范围，也不把浏览器默认工具集扩展到更多高风险工具。

## Decisions

### 1. 在技能加载结果中保留“可执行技能目录”元数据

**选择：** runtime 在解析 `load_skill` 结果时，除了技能正文，还要保留技能的来源路径；如果该技能来自文件系统中的 `SKILL.md`，则派生其父目录作为“技能执行目录”。

**原因：** 当前 `sessions.SkillEntry` 已经保留了 `Path`，直接从已有字段派生目录即可，不需要引入新的存储模型。这样可以同时覆盖内置技能和本地挂载技能，并让 DB skill 自然落到“无目录”的回退分支。

**备选方案：**
- 在 skill 正文中增加额外约定字段（如 frontmatter 的 cwd）——需要改写技能格式，成本更高。
- 让模型自己从 `<runtime-paths>` 推断技能目录——不可靠，且无法驱动服务端默认 cwd 逻辑。

### 2. 技能目录只影响“由当前激活技能驱动的后续工具调用”

**选择：** runtime 为当前回合维护一个“活动技能上下文”。当最近一次成功加载的是带本地目录的技能时，后续工具调用默认在该技能目录执行；若没有活动技能目录，则继续使用 workspace 根目录。

**原因：** 用户要的是“执行 Skill 时自动切到 Skill 目录”，而不是把所有对话永久迁移到技能目录。把作用域限制在当前回合、当前活动技能，可以最大程度复用现有循环，又避免引入 conversation 级目录状态。

**备选方案：**
- 对所有技能描述预先绑定目录——模型未真正使用该技能时也会污染默认 cwd。
- 将 cwd 永久切到最后一个技能目录——容易影响后续普通对话和非技能工具调用。

### 3. 技能目录切换必须继续受 workspace 边界约束

**选择：** 只有当技能目录本身位于允许的 runtime workspace 边界内时，才允许把它作为默认 cwd；否则拒绝切换并回退/报错，避免工具被带到未授权目录。

**原因：** 现有工具安全模型的核心是假设所有文件与命令访问都受 workspace 边界约束。即使技能来源于磁盘，也不能因为加载了某个 skill 就突破该边界。

**备选方案：**
- 无条件信任技能目录——会把 `load_skill` 变成新的越权入口。
- 一律复制技能资源到 workspace 再执行——引入额外同步与部署复杂度，不适合本次需求。

### 4. 审计继续以 resolved cwd 为主，并补充技能目录相关测试

**选择：** 保持现有 audit 结构以 `resolved_cwd` 为主，不额外扩展大量字段；通过测试确保当工具因技能驱动切换目录时，审计中的 cwd 能准确反映技能目录。

**原因：** 当前审计数据已经以 resolved cwd 为核心，能够直接回答“实际在哪个目录执行”。只要把该值切换正确，就能满足排查需求，避免本次变更扩散到存储模型与前端展示。

**备选方案：**
- 新增 `skill_name`、`skill_dir` 等独立字段——可读性更强，但会扩大 schema 和兼容面。

## Risks / Trade-offs

- **[Risk] 活动技能上下文与普通对话消息交错后可能导致默认 cwd 不符合模型预期** → 将规则收敛为“仅最近一次成功加载且可解析目录的技能生效”，并补充多次 `load_skill` 覆盖测试。
- **[Risk] DB skill 没有稳定目录，行为与文件技能不同** → 明确回退到 workspace 根目录，并在规格和测试里固定这一差异。
- **[Risk] 技能目录若靠近 workspace 边界，路径校验实现不当可能产生绕过** → 复用现有绝对路径归一化与边界判断逻辑，不单独实现一套字符串前缀判断。
- **[Trade-off] 不持久化技能 cwd 会让跨轮“记住上次技能目录”能力缺失** → 先满足执行 Skill 当下的自动切换需求，避免引入 conversation 状态复杂度。

## Migration Plan

1. 调整 runtime 的技能加载与工具上下文结构，使其能携带活动技能目录。
2. 更新工具默认 cwd 解析与审计测试，确保成功、回退和拒绝路径都被覆盖。
3. 部署时无需数据迁移；若出现回归，可回滚到现有“始终以 workspace 根目录为默认 cwd”的实现。
