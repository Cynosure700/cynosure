# 清除 cynosure 冗余字段设计文档

## 1. 背景与目标

随着"任意目录运行""统一文档存储"等改造完成，cynosure 中以下字段已成为冗余或需要清除：

1. `CommandBinDir`（命令 bin 目录）
2. `CommandScriptDir`（命令脚本目录）
3. `BuiltinSkillsDir`（内置技能目录）
4. 工具执行上下文（`tools.RuntimeEnv`）中的 `AppHome`（即 `app_home` 参数）

目标：删除上述字段及其全部关联代码，同步更新受影响的功能逻辑与测试，且不破坏其余现有功能（编译通过、测试通过）。

> 说明：经与需求方确认，`CommandBinDir`/`CommandScriptDir` 当前仍承载 bash 命令白名单、命令审计路径解析、以及 `~/.cynosure/bin`、`~/.cynosure/cmd` 目录创建/校验等功能。本次为**确认全部清除（含相关功能）**，因此下文会一并移除这些功能链路。

## 2. 现状依赖梳理

- 读取：**无任何业务读取**

### 2.2 工具上下文 `RuntimeEnv.AppHome`（纯冗余，只写不读）
- 定义：`tools/runtime_env.go:11`
- 赋值：`agent/runtime/tool_registry.go:122`、`agent/runtime/tool_registry.go:184`
- 读取：工具执行链路无消费方（仅测试 `runtime_test.go` 读取断言）

> 注意：`config.AppConfig.AppHome` / `fileConfig.AppHome` 仍被 `paths.go` 的目录创建/校验使用，**不属于本次"工具执行上下文 app_home"清除范围**，保持不动。

### 2.3 `CommandBinDir` / `CommandScriptDir`（含功能，确认清除）

工具运行时层：
- 定义：`tools/runtime_env.go:12-13`
- 赋值：`agent/runtime/tool_registry.go:123-124`、`agent/runtime/tool_registry.go:185-186`

功能消费方（本次将一并移除）：

## 3. 改动方案

### 3.1 配置层 `config/config.go`
- 删除 `fileConfig` 中字段：`BuiltinSkillsDir`、`CommandBinDir`、`CommandScriptDir`（行 21-23）
- 删除 `AppConfig` 中字段：`BuiltinSkillsDir`、`CommandBinDir`、`CommandScriptDir`（行 37-39）
- 删除 `defaultFileConfig()` 中默认值：`BuiltinSkillsDir`、`CommandBinDir`、`CommandScriptDir`（行 56-58）
- 保留 `AppHome` 字段不动（仍被 paths.go 使用）

### 3.2 配置层 `config/local_config.go`
- 删除 `LoadLocalConfig` 中 `binDir`/`scriptDir` 的获取逻辑（行 47-54）
- 删除 `AppConfig{}` 字面量中 `BuiltinSkillsDir`、`CommandBinDir`、`CommandScriptDir` 的赋值（行 67-69）
- 删除不再被引用的函数 `CynosureBinDir()`（行 204-210）、`CynosureScriptDir()`（行 212-218）

### 3.3 目录布局 `config/paths.go`
- `EnsureAppLayout`：删除 `command bin dir`、`command script dir` 两项（行 17-18）
- `ValidateAppLayout`：删除 `command bin dir`、`command script dir` 两项（行 39-40）
- 保留 `app home`、`workspace root` 两项

### 3.4 工具运行时上下文 `tools/runtime_env.go`
- 删除 `RuntimeEnv` 中字段：`AppHome`、`CommandBinDir`、`CommandScriptDir`（行 11-13）
- 删除 `systemAssetDirsFromContext()` 函数（行 57-69）——其唯一作用是返回这两个目录

### 3.5 bash 白名单 `tools/handlers.go`
- 行 65：`validateBashCommandPaths(root, cmd, allowOutsideWorkspaceFromContext(ctx), systemAssetDirsFromContext(ctx)...)`
  改为不再传入 systemAssetDirs：`validateBashCommandPaths(root, cmd, allowOutsideWorkspaceFromContext(ctx))`
- `tools/path_guard.go` 的 `validateBashCommandPaths(root, command, allowOutsideWorkspace bool, allowedDirs ...string)` 签名保留可变参数即可（传空），无需改动函数体；`isUnderAnyDir` 在 allowedDirs 为空时自然返回 false，行为正确。

  > 影响说明：清除后，bash 工具将不再把 `~/.cynosure/bin`、`~/.cynosure/cmd` 视为工作区外的白名单目录。即在 `BashAllowOutsideWorkspace=false` 时，调用这两个目录下的命令将被判定为越界。这是"确认清除相关功能"的预期行为。

### 3.6 工具注册 `agent/runtime/tool_registry.go`
- `runtimeEnv()`：删除 `AppHome`、`CommandBinDir`、`CommandScriptDir` 三处赋值（行 122-124）
- `runtimeEnvFromConfig()`：删除 `AppHome`、`CommandBinDir`、`CommandScriptDir` 三处赋值（行 184-186）

### 3.7 命令审计 `agent/runtime/hooks/tool.go`
- `toolAuditPreHook`（行 20-28）：当前依赖 `runtimeEnv.CommandBinDir`/`CommandScriptDir` 做命令产物路径解析。清除后需调整：
  - 行 22：移除对 `CommandBinDir`/`CommandScriptDir` 的引用。
  - 决策点（见第 5 节）：命令审计中 `ResolvedCommandPath` / `CommandArtifactPath` / `CommandArtifactSource` 三个审计字段是否一并清除。

## 5. 待确认决策点

命令审计字段 `ResolvedCommandPath` / `CommandArtifactPath` / `CommandArtifactSource`（定义于 `hooks/types.go:100-102`，写入于 `hooks/tool.go:24-26`，序列化于 `types.go:145-147`）依赖 `CommandBinDir`/`CommandScriptDir` 来识别"命令产物来源"。清除这两个目录字段后，有两种处理方式：

- **方案 A（最小改动，推荐）**：保留审计字段与 `resolveCommandPaths`/`classifyCommandArtifactSource` 逻辑，仅去掉对 `CommandBinDir`/`CommandScriptDir` 的传参（`resolveCommandPaths(h.Name, h.RawArgs)` 不再传 roots）。此时 `CommandArtifactPath`/`CommandArtifactSource` 对工作区内命令仍可识别为 `workspace`，工作区外为空/`custom`，审计能力基本保留。
- **方案 B（彻底清除）**：连同 `ResolvedCommandPath`/`CommandArtifactPath`/`CommandArtifactSource` 审计字段、`resolveCommandPaths`、`classifyCommandArtifactSource` 一并删除，审计仅保留 `ResolvedCWD`/`OutcomeSummary`/`DenialReason`。

> 我倾向方案 A：命令审计本身不是"冗余字段"，仅是消费了将被删除的目录字段；保留它对功能影响最小。最终以你的选择为准。
