# 输入框光标定位优化设计文档

## 1. 背景与需求

当前 TUI（`internal/tui`）的输入框存在问题：用户把**多行内容复制**进输入框后，可见光标（`█`）不在内容末尾，而是停留在很靠前的位置。

用户期望：复制内容后，光标停在内容的最后。

### 约束（不可破坏的现有能力）

- **鼠标/触控板滑动滚动会话历史**必须保持原样。在当前渲染模式（`tea.WithAltScreen()` 且**关闭鼠标上报**，见 `newRunConfig`）下，macOS 触控板两指滑动会被终端翻译成 `↑`/`↓` 方向键发给程序，并由 `updateViewportScroll`（`app.go:360`）消费来滚动 viewport。因此本次**完全不触碰 `↑`/`↓` 方向键的处理逻辑**，避免与触控板滑动抢键。
- 终端原生选择/复制文本能力不变（项目未开启 `WithMouseCellMotion`）。
- 现有可见光标在单行输入、行中编辑（左右键）下的表现保持不变。

> 说明：曾考虑同时实现「方向键回溯历史输入」，但在当前关闭鼠标上报的模式下，触控板滑动 == `↑`/`↓`，二者会抢同一个键，破坏滚动体验。经与用户确认，本次**仅修复光标定位 bug，不改动方向键**。历史回溯如需要，可作为后续单独需求（需配合按键方案设计）。

## 2. 根因分析

可见光标由自定义渲染函数 `renderInput`（`internal/tui/app.go:1963`）绘制，而非 `textarea.View()`。它的做法是：

```go
lineInfo := m.input.LineInfo()
beforeCursor, afterCursor := splitInputAtCursor(text, lineInfo.StartColumn+lineInfo.ColumnOffset)
```

即用 `lineInfo.StartColumn + lineInfo.ColumnOffset` 作为「在整段文本里的绝对偏移」去切分 `Value()` 全文，然后在中间插入 `█`。

但 `bubbles/textarea` 的 `LineInfo()`（`textarea.go:816`）返回的 `StartColumn`、`ColumnOffset` 都是**相对于「当前逻辑行」**（`m.value[m.row]`）的，而不是相对于全文。二者之和恰好等于当前行内列号 `m.col`，**不包含光标所在行之前各行的长度**。

- 单行输入时 `m.row == 0`，行内偏移就等于全文偏移，所以现在看起来是对的。
- 多行（粘贴）后，光标落在最后一行，`m.col` 只是最后一行内的列号（粘贴末尾通常很小甚至为 0），于是 `█` 被画到了全文很靠前的位置 —— 这就是 bug。

关键点：粘贴后 textarea **内部**的光标其实已经在内容末尾（`insertRunesFromUserInput` 会把 `m.row/m.col` 移到插入内容末尾，`textarea.go:437-447`）。所以问题纯粹出在「自定义渲染时把行内偏移误当成全文偏移」，**无需**强行移动光标，只要把渲染偏移算对即可。

## 3. 方案设计

新增方法计算光标在 `Value()` 全文中的**绝对 rune 偏移**：累加光标所在行之前各逻辑行的 rune 长度（每行 +1 计入换行符），再加上当前行内列号。

```go
// inputCursorOffset 返回光标在整段输入文本中的绝对 rune 偏移，
// 兼容多行（粘贴）输入：textarea 的 LineInfo 偏移是「行内」相对值，
// 这里把光标行之前各逻辑行的长度（含换行符）累加进来。
func (m Model) inputCursorOffset() int {
    li := m.input.LineInfo()
    colWithinRow := li.StartColumn + li.ColumnOffset // 行内列号 == m.col
    row := m.input.Line()                            // 当前逻辑行
    rows := strings.Split(m.input.Value(), "\n")
    offset := 0
    for i := 0; i < row && i < len(rows); i++ {
        offset += len([]rune(rows[i])) + 1 // +1 为该行末尾的换行符
    }
    return offset + colWithinRow
}
```

`renderInput` 改为用该偏移切分：

```go
beforeCursor, afterCursor := splitInputAtCursor(text, m.inputCursorOffset())
```

- `splitInputAtCursor` 已有 `min/max` 夹取，越界安全，保持不动。
- 粘贴后 textarea 内部光标已在末尾，此修复让可见 `█` 渲染到末尾，满足「复制内容后光标在内容的最后」。
- 单行输入时 `row==0`，结果与现状完全一致，不影响左右键行中编辑、空输入占位符等既有行为。

## 4. 影响面与兼容性

| 区域 | 影响 | 说明 |
|------|------|------|
| 鼠标/触控板滑动滚动会话 | 无 | 不触碰 `↑`/`↓` 与 `updateViewportScroll`、`newRunConfig`、`MouseMsg` |
| 终端原生选择/复制 | 无 | 不开启鼠标上报 |
| 单行输入 / 左右键行中编辑 | 无 | `row==0` 时绝对偏移 == 行内偏移，渲染一致 |
| 多行粘贴光标 | 修复 | 光标渲染到内容末尾 |

2. **单行/行中编辑光标不回归**：复用现有 `TestLeftArrowMovesVisibleInputCursorForMiddleEditing`、`TestTypingSpaceRefreshesInlinePrompt` 等，保持通过。
