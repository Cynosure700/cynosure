# 记忆类型重构设计文档

## 1. 背景与目标

cynosure 当前的长期记忆抽取机制把对话中的durable信息分为三类：

- `episodic_memory`（会话经历/事件）
- `user_preference`（用户偏好/约束/习惯）
- `project_fact`（项目事实：架构、命令、约定、依赖、已知约束、实现决策）

相关实现：

- 抽取：`internal/agent/runtime/memory.go` 的 `extractMemories` 在每轮结束后异步调用 LLM，解析为 `storage.Memory`，落盘到 `~/.cynosure/memory/<workspace-key>/`。
- 注入：`selectRelevantMemories` 启动/请求前让 LLM 从候选记忆里挑选，再由 `renderMemorySection` 渲染进系统提示词。
- 合并/裁剪：`maybeConsolidateUserPreferences`、`maybeConsolidateProjectFacts`、`maybePruneSessionSummaries`。
- 提示词资产：`assets/prompts/memory_extraction.md`、`memory_selection.md`、`memory_consolidation.md`。

存在的问题：`project_fact` 大量记录了**可从代码/Git 直接读取**的内容（架构、文件路径、命令、约定），这些信息既冗余又容易过时；`episodic_memory` 偏向流水账，价值低。

### 目标

把记忆类型重构为下面**四类**，并收紧抽取提示词，避免记录可从代码、Git、调试上下文或 `CYNOSURE.MD` 直接获得的内容：

| type 值 | 中文名 | 记什么 | body 结构 |
|---|---|---|---|
| `preference` | 用户喜好与约束 | 用户长期偏好、习惯，以及项目相关描述（如"我使用 Go 语言"） | 自由文本 |
| `feedback` | 行为指导 | 对 Agent 行为的纠正**和**肯定 | 规则 + `Why:` + `How to apply:` |
| `project` | 项目动态 | 项目进展、决策、截止日期（不可从代码推导的部分） | 事实 + `Why:` + `How to apply:`；相对日期转绝对日期 |
| `reference` | 外部引用 | 外部系统中信息的定位信息 | 自由文本 |

### 非目标 / 约束

- **会议（会话）记忆提取策略不变**：`conversation_memory_update.md` 提示词、`internal/agent/runtime/conversation_memory.go`（`updateConversationMemory` / `parseConversationMemories`）、`internal/agent/runtime/compression/conversation_memory_strategy.go`（`ConversationMemoryStrategy`）以及 `storage.ConversationMemory` 全部保持不动。本次只改"长期记忆"链路。
- **不引入作用域（scope）字段**：需求中描述了 private/team 作用域语义，但 cynosure 是纯本地单用户 Markdown 存储，没有团队/共享后端。本次不落地 scope，仅在提示词层面以中文说明触发时机，不写入任何 scope 元数据，避免引入无意义且无法消费的字段（YAGNI）。
- **旧类型硬切换**：`validMemoryType` 只接受新四类；抽取/写入阶段不再产生旧类型。读取与注入阶段对磁盘上残留的旧类型文件（`episodic_memory`、旧语义 `project_fact`、`user_preference`）直接跳过，不注入也不报错。不做数据迁移。
- **body 结构靠提示词约束**，Go 侧不做 `Why:`/`How to apply:` 的硬校验，避免误伤模型输出格式的细微差异导致整条记忆被丢弃。

## 2. 类型语义与触发规则（写入提示词）

抽取提示词需明确告诉模型四类的记什么、何时触发、body 结构。

### 2.1 preference — 用户喜好与约束

- 记什么：用户长期偏好、习惯、技术栈约束，以及项目相关的稳定描述。例："我使用 Go 语言""回答用中文""喜欢简洁的实现"。
- 触发时机：用户表达稳定偏好或约束时。
- body：自由文本，简洁说明偏好内容。

### 2.2 feedback — 行为指导

- 记什么：对 Agent 行为的**纠正**和**肯定**。不只记失败，也记被验证有效的好做法。
- 触发时机：
  - 用户纠正（"不要…""别再…"）。
  - 用户确认有效做法（"就这样做""以后都这么处理"）。
- body 结构（必须）：
  - 第一行：规则本身。
  - `Why:` 为什么这条规则成立。
  - `How to apply:` 下次如何应用。
- 设计说明：同时记录成功与失败。只保存纠正会避免过去的错误，但会偏离用户已验证的好方法，且可能让 Agent 变得过于谨慎——所以肯定类反馈同样要记。

### 2.3 project — 项目动态

- 记什么：用户正在进行或长期维护的项目相关信息——项目进展、决策、截止日期。仅限**不可从代码推导**的部分。
- 触发时机：了解到谁在做什么、为什么、截止日期时。
- body 结构（必须）：事实 + `Why:` + `How to apply:`。
- 特殊规则：**相对日期必须转换为绝对日期**。提示词中提供当前日期作为锚点（运行时注入今天日期，例如 `2026-06-18`），让模型把"下周三""三天后"换算成 `YYYY-MM-DD`。

### 2.4 reference — 外部引用

- 记什么：外部系统中信息的定位信息（如"部署配置在 X 仓库的 Y 文件""监控面板在 Z 平台的 W 看板"）。
- 触发时机：了解到外部系统中信息位置时。
- body：自由文本，写清"在哪个外部系统的哪个位置有什么"。

### 2.5 禁止抽取的内容（提示词显式排除）

抽取提示词必须显式列出**不该提取**的内容：

- 代码模式、约定、架构、文件路径、项目结构——读当前代码即可获得。
- Git 历史、最近的改动、谁改了什么——`git log` / `git blame` 是权威来源。
- 调试方案或修复步骤——修复在代码里，上下文在 commit 消息中。
- 已经记录在 `CYNOSURE.MD` 中的内容。
- 临时任务细节：进行中的工作、临时状态、当前对话上下文（这些由"会话记忆"链路负责，不进长期记忆）。

## 3. 代码改动

### 3.1 类型常量与校验（`internal/agent/runtime/memory.go`）

替换三个常量为四个：

```go
const (
    MemoryTypePreference = "preference"
    MemoryTypeFeedback   = "feedback"
    MemoryTypeProject    = "project"
    MemoryTypeReference  = "reference"
)
```

`validMemoryType` 改为只接受这四类。`extractedMemory` 结构不变（`name/type/description/body`）。

阈值常量调整命名（沿用现有数值，行为不变）：

- `maxPreferenceMemories`（preference）
- 其余三类各自的上限常量；保留 `maxInjectedMemories`、字段长度上限、`maxMemoryDialogueChars` 不变。

> 旧的 `episodic_memory` 走的是"裁剪最老"（`maybePruneSessionSummaries` + `DeleteOldestMemories`）；`user_preference`/`project_fact` 走"LLM 合并"。本次四类统一改为 **超过阈值时用 LLM 合并**（`consolidateViaLLM` + `ReplaceMemoriesByUserAndType`），不再保留"裁剪最老"分支，逻辑更一致。`feedback`/`project`/`reference`/`preference` 各自独立判阈值与合并。

### 3.2 抽取后的分类与合并（`extractMemories`）

`extractMemories` 的 `switch it.Type` 改为对四类分别置脏标记；结尾对被触达的类型调用通用的"按类型合并"入口：

```go
func (s *Service) maybeConsolidateType(ctx context.Context, userID, memType string, max int) {
    items, err := s.Store.ListMemoriesByUserAndType(ctx, userID, memType)
    if err != nil || len(items) < max {
        return
    }
    refined := s.consolidateViaLLM(ctx, memType, memType, items)
    if refined == nil {
        return
    }
    if err := s.Store.ReplaceMemoriesByUserAndType(ctx, userID, memType, refined); err != nil {
        logger.Warn(...)
    }
}
```

移除 `maybeConsolidateProjectFacts`、`maybePruneSessionSummaries` 及其专用的 store 方法依赖（见 3.4）。`consolidateViaLLM` 的签名保持 `(typeLabel, typeValue, items)`，`typeLabel` 直接用 type 值即可。

### 3.3 注入渲染（`renderMemorySection`）

`renderMemorySection` 当前按 `user_preference`/`episodic_memory`/`project_fact` 分组渲染中文小节。改为按四类分组：

- preference → "用户喜好与约束"
- feedback → "行为指导"
- project → "项目动态"
- reference → "外部引用"

保留现有结构：顶部"当前项目记忆（仅适用于当前项目）"说明，每条 `名称：描述` + 缩进 body。未知/旧类型不渲染。

### 3.4 Store 接口收敛（`internal/agent/runtime/runtime.go` + `internal/local/store.go` + `internal/local/memory_store.go`）

现有接口里有 `project_fact` 专用方法：`ListProjectFactMemories`、`CountProjectFactMemories`、`ReplaceProjectFactMemories`。四类统一走通用的 `ListMemoriesByUserAndType` / `CountMemoriesByUserAndType` / `ReplaceMemoriesByUserAndType` 后，这些专用方法不再需要。

方案：**删除三个 `*ProjectFact*` 专用方法**，调用方改用通用方法。涉及：

- `conversationStore` 接口（runtime.go）去掉三行。
- `local/store.go` 去掉三个转发方法（`ListProjectFactMemories`/`CountProjectFactMemories`/`ReplaceProjectFactMemories`）。
- `local/memory_store.go` 去掉对应实现，并把 `InsertMemory` 里 `mem.Type == ""` 的默认值从 `"user_preference"` 改为 `"preference"`。
- `runtime_test.go` 的 `fakeStore` 去掉这三个方法。

> `memory_store.go` 的 Markdown 落盘格式（front matter、`metadata.type`、索引、原子写入）保持不变，只是 `metadata.type` 现在写入新四类值之一。

### 3.5 提示词资产

- `assets/prompts/memory_extraction.md`：重写为四类 + 触发规则 + body 结构 + 禁止抽取清单。新增对"当前日期"占位符的使用，用于 project 类型的相对→绝对日期转换。
- `assets/prompts/memory_selection.md`：基本不变（仍是按索引选择），措辞同步为四类。
- `assets/prompts/memory_consolidation.md`：模板仍用 `{{type_label}}`/`{{type_value}}`，补充"合并时保留 `Why:`/`How to apply:` 结构（feedback/project）"的说明。
- `assets/prompts/conversation_memory_update.md`：**不动**。
- `assets/prompts/README.md`：同步描述。

#### 当前日期注入

`project` 类型要求相对日期转绝对日期，需要把"今天"传给抽取提示词。方案：在 `memoryExtractionSystemPrompt()` 里把模板中的 `{{current_date}}` 占位符替换为 `time.Now().Format("2006-01-02")`（与 `memoryConsolidationSystemPrompt` 的占位符替换方式一致）。若模板无占位符则不替换，保持向后兼容。

### 3.6 README

`cynosure/README.md` 第 109 行附近关于"长期记忆类型包括 user_preference / episodic_memory / project_fact"的描述，更新为四类说明。

## 4. 数据流（不变的部分 + 变化的部分）

```
每轮结束 (scheduleMemoryWork, 异步)
  └─ extractMemories               [变化: 四类 + 新提示词 + 当前日期注入]
       ├─ InsertMemory             [不变: Markdown 落盘]
       └─ maybeConsolidateType×N   [变化: 四类统一 LLM 合并]
  └─ updateConversationMemory      [不变: 会话记忆链路]

请求前 (selectRelevantMemories)
  └─ ListRelevantMemories          [不变: 读 memory.md 索引]
  └─ LLM 选择索引                   [不变]
  └─ renderMemorySection           [变化: 四类分组 + 跳过旧类型]
```

## 5. 错误处理与兼容性

- 磁盘上残留旧类型文件：`ListRelevantMemories` 仍会读出（`storage.Memory.Type` 为旧值），但 `renderMemorySection` 的 `switch` 不匹配任何分组 → 不注入；`ListMemoriesByUserAndType(newType)` 不会命中旧类型 → 不参与新合并。旧文件保持原样，不删除、不报错。
- 抽取/合并失败：沿用现有 best-effort——记 warning 并吞掉，不影响用户响应。
- body 缺少 `Why:`/`How to apply:`：不丢弃（Go 不校验结构），仍按原文落盘。
