## 评测基准介绍

### Terminal-Bench

Terminal-Bench 面向“真实终端环境中的 agent 能力”评测。每个任务都提供独立的容器环境、自然语言指令、测试脚本和参考解；`tb run` 会启动任务容器，让 agent 在容器内操作 shell、文件系统、构建工具或服务，最后运行任务自带 verifier 判定是否完成。其官方单题评分是二值分：`is_resolved=true` 记 1 分，否则记 0 分；总分为 `resolved / total`。

本次使用 `terminal-bench-core==0.1.1`，选取 30 个 trial，覆盖文件操作、数据处理、安全、软件工程、系统调试等类型。Terminal-Bench 的 `task.yaml` 提供官方 `difficulty` 与 `category` 字段，因此结果表中补充了逐题难度和类别。

### SWE-bench Lite

SWE-bench 面向“真实 GitHub issue 修复能力”评测。每个实例包含真实仓库、base commit、issue 描述和测试集合。评测流程分为两段：先由 agent 生成符合 SWE-bench JSONL 格式的 `model_patch`，再由官方 harness 将 patch 应用到容器内仓库并运行 `FAIL_TO_PASS` 与 `PASS_TO_PASS` 测试。其官方单题评分也是二值分：`resolved=true` 记 1 分，否则记 0 分；总分为 `resolved / total`。

本次使用 `princeton-nlp/SWE-bench_Lite` 的 `test` split 前 30 个实例。SWE-bench Lite 数据集字段包括 `repo`、`base_commit`、`problem_statement`、`patch`、`test_patch`、`FAIL_TO_PASS`、`PASS_TO_PASS` 等，但没有逐题 `difficulty` / `level` 字段，因此报告不为 SWE-bench Lite 编造官方难度评级。

### 评分口径

| 基准                        | 单题评分                            |              本次总分 |
| ------------------------- | ------------------------------- | ----------------: |
| Terminal-Bench Core 0.1.1 | `is_resolved=true` 记 1 分，否则 0 分 | `18 / 30 = 60.0%` |
| SWE-bench Lite            | `resolved=true` 记 1 分，否则 0 分    | `26 / 30 = 86.7%` |

报告中的 `agent_timeout`、`patch bytes`、`agent completed` 是诊断指标，不计入官方分数；官方分数只看最终 verifier / test 是否 resolved。

## 环境搭建

### 公共环境

本次测评在本地 macOS / Apple Silicon 环境中执行，依赖本机 Docker Desktop 运行 Linux 容器。基础工具与配置如下：

| 项目              | 配置                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------- |
| Go              | `go1.26.1 darwin/arm64`                                                                   |
| Python          | `Python 3.14.5`                                                                           |
| Docker          | Docker Desktop，Linux container 后端                                                         |
| Terminal-Bench  | `terminal-bench==0.2.18`，通过 `uv tool install terminal-bench` 安装                           |
| SWE-bench       | `swebench==4.1.0`，通过 Python package 使用官方 harness                                          |
| Cynosure LLM 配置 | `~/.cynosure/settings.json`，包含 `env.open_auth_token`、`env.open_model`、`env.open_base_url` |

为避免 TUI 交互影响自动化，本次新增并使用 one-shot eval 入口：

```bash
go build -o <run_dir>/cynosure-eval-agent-host ./evals/cmd/cynosure-eval-agent
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 \
  go build -o <run_dir>/cynosure-eval-agent-linux-arm64 ./evals/cmd/cynosure-eval-agent
```

其中 `cynosure-eval-agent-host` 用于 SWE-bench 推理阶段，`cynosure-eval-agent-linux-arm64` 用于 Terminal-Bench 任务容器内执行。

### Terminal-Bench 环境

Terminal-Bench 采用官方 task container 机制。每个任务目录包含 `Dockerfile`、`docker-compose.yaml`、`task.yaml`、`run-tests.sh` 和测试文件；`tb run` 会构建任务容器，启动 tmux session，让 agent 在容器内完成任务，再运行任务自带测试脚本。

本次执行工作：

1. 安装并确认 `tb` CLI 可用。
2. 构建 Linux 版 `cynosure-eval-agent`。
3. 编写 `evals/terminal_bench/cynosure_agent.py`，实现 Terminal-Bench `BaseAgent`：复制二进制和 settings、写入任务 instruction、开启 `bypassPermissions`、执行 one-shot agent。
4. 使用显式任务列表运行 30 个 trial，避免默认按最长任务优先导致整体耗时不可控。
5. 使用 `--cleanup` 清理每个任务的 Docker image / volume。

代表性命令：

```bash
tb run \
  --dataset terminal-bench-core==0.1.1 \
  --task-id hello-world \
  --task-id csv-to-parquet \
  --task-id grid-pattern-transform \
  --n-concurrent 1 \
  --output-path evals/runs/tb30-20260629/terminal_bench \
  --run-id tb30-20260629 \
  --agent-import-path cynosure_agent:CynosureTerminalBenchAgent \
  --agent-kwarg binary_path=evals/runs/tb30-20260629/cynosure-eval-agent-linux-arm64 \
  --agent-kwarg settings_path=/<PATH>/.cynosure/settings.json \
  --agent-kwarg timeout_sec=1200 \
  --global-test-timeout-sec 900 \
  --cleanup \
  --no-upload-results
```

实际执行时拆成两个批次：`tb30-20260629` 保留已完成的 14 个官方结果，`tb30b-20260629` 补跑 16 个不同任务，最终合并为 30 个官方 trial。

### SWE-bench Lite 环境

SWE-bench Lite 官方评测分为两个阶段：先生成 `predictions.jsonl`，再由 `swebench.harness.run_evaluation` 应用 patch 并运行测试。

本次执行工作：

1. 使用 `datasets` 读取 `princeton-nlp/SWE-bench_Lite` 的 `test` split。
2. 选择前 30 个实例，记录到 `evals/runs/swe30-20260629/swe_bench/selected_instances.json`。
3. 编写 `evals/swe_bench/run_cynosure_swebench.py`：逐例 clone、checkout、生成 prompt、调用 Cynosure、收集 `git diff`、写入 `predictions.jsonl`。
4. 将 30 条 prediction 交给 SWE-bench 官方 harness。
5. 对 Apple Silicon 环境问题进行分批补跑：可用实例优先使用 arm64 环境，两个 Astropy 实例提前拉取对应 x86\_64 实例镜像后单独评测。

Patch 生成命令：

```bash
python3 evals/swe_bench/run_cynosure_swebench.py \
  --binary evals/runs/swe30-20260629/cynosure-eval-agent-host \
  --settings /<PATH>/.cynosure/settings.json \
  --output-dir evals/runs/swe30-20260629/swe_bench \
  --n 30 \
  --timeout-sec 600 \
  --resume
```

官方测试命令：

```bash
python3 -m swebench.harness.run_evaluation \
  --dataset_name princeton-nlp/SWE-bench_Lite \
  --predictions_path evals/runs/swe30-20260629/swe_bench/predictions.jsonl \
  --instance_ids <selected 30 instance ids> \
  --max_workers 1 \
  --timeout 1800 \
  --run_id swe30-20260629 \
  --report_dir evals/runs/swe30-20260629/swe_bench \
  --clean false \
  --namespace none
```

运行中处理过的环境问题：

| 问题                                                       | 处理                                                                                            |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Docker Hub 拉取 `ubuntu:22.04` 超时                          | 从 `public.ecr.aws/docker/library/ubuntu:22.04` 预拉镜像辅助构建                                       |
| x86\_64 本地 Docker build 中 Miniconda 触发 Rosetta/loader 错误 | 对可用实例优先使用 arm64 本地环境；对 arm64 不兼容的 Astropy 实例，提前拉取对应 x86\_64 实例镜像                              |
| arm64 Conda channel 缺少旧 Astropy 依赖                       | 对 `astropy__astropy-6938`、`astropy__astropy-7746` 补拉 `swebench/sweb.eval.x86_64...` 实例镜像后单独评测 |
| GitHub clone 偶发失败                                        | 删除失败 case 的中间状态，重新执行 patch 生成                                                                 |
| 运行产物膨胀                                                   | 每个 SWE case 结束后删除 `workspace/repo`，Terminal-Bench 运行后删除 `.cast` 录屏和临时二进制                      |
