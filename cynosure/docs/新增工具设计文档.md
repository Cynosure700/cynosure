# 新增工具设计文档：grep / glob / ls / multi_edit / web_fetch / web_search

## 1. 背景与目标

为 cynosure（Go 模块 `cynosure`）的本地 Agent 运行时新增 6 个工具，补齐"代码检索 / 文件浏览 / 批量编辑 / 联网"能力：

| 需求名 | 注册名（snake_case） | 能力简述 |
| --- | --- | --- |
| grep | `grep` | 基于正则的文件内容搜索（纯 Go 实现） |
| glob | `glob` | 文件名 glob 模式匹配 |
| ls | `ls` | 列出目录文件，支持 ignore 模式 |
| mutileEdit | `multi_edit` | 单文件多处查找替换（基于 edit 语义） |
| webFetch | `web_fetch` | 抓取 URL → 转文本 → LLM 处理 |
| websearch | `web_search` | 联网搜索（本期占位，未配置后端时返回提示） |

### 约束（来自需求与现状）
- **不影响现有功能实现**：仅新增代码与定义，不改动 `bash/read_file/write_file/edit_file/load_skill/todo_write/spawn_subagent/read_persisted_output` 的既有行为。
- 工具命名采用 **snake_case**，与现有工具（`read_file`、`edit_file`）保持一致。
- `grep` **纯 Go 实现**（`regexp` + 文件遍历），不依赖外部 `rg`/`grep` 二进制。
- `web_search` **本期占位**：注册工具定义，但未配置搜索后端时返回明确提示，便于后续接入。
- 所有路径类工具复用统一的路径解析（`safety.SafePathFromRoot` + `path_guard.go` 的 `resolvePathFromContext`，将相对路径基于 cwd 解析并清理为绝对路径）。注意：当前实现不再强制“禁止逃逸 workspace”，越界保护已由交互式审批机制（`internal/tools/approval.go` + 工作区 `.cynosure/settings.json`）接管。

## 2. 现状梳理（关键集成点）

工具体系当前的关键文件与职责：

- `internal/tools/definitions.go`
  - `baseToolDefs`：内置工具的 OpenAI Tool 定义；`AllToolDefs`、`ChildToolDefs`。
  - 辅助构造器：`toolDef/strParam/intParam`。
- `internal/tools/handlers.go`
  - `Handlers` map：工具名 → `ToolHandler`。
  - `Dispatch`：统一执行入口，非 `bash` 工具有 `normalToolTimeout`(60s) 看门狗。
- `internal/tools/file_ops.go`：`RunReadFromRoot/RunWriteFromRoot/RunEditFromRoot`。
- `internal/tools/path_guard.go`：`resolvePathFromContext`（相对路径基于 cwd 解析 + workspace 约束）、`validatedWorkspaceRootFromContext`。
- `internal/tools/runtime_env.go`：`RuntimeEnv` 与 context 注入（`WithRuntimeEnv`）。
- `internal/tools/validation.go`：基于 JSON Schema 的参数校验（注册时自动生效）。
- `internal/agent/runtime/tool_registry.go`
  - `lookupRegisteredTool` 从 `agenttools.AllToolDefs` 中查；
  - `loadAllowedToolNames` 依据 `cfg.AllowedTools` 过滤启用的工具；
  - `Execute` 调 `agenttools.Dispatch`；`web_*`/`spawn_subagent`/`mcp__*` 之外的工具走通用路径。
- `internal/config/local_config.go`
  - `defaultLocalAllowedTools`：默认启用的工具清单（CSV）。
- `cn/tools/index.json` 与 `cn/tools/*.md`：中文工具描述文案的参考来源（已包含 Grep/Glob/LS/MultiEdit/WebFetch/WebSearch 文案，可直接复用作 Description）。

> 重要发现：`tool_registry.go` 仅注册 `cfg.AllowedTools` 中列出的工具。**新工具必须同时加入 `defaultLocalAllowedTools`，否则默认不会暴露给模型。**

> web_fetch 需要 LLM 处理内容。`Service` 持有 `LLM llm.Client`，但 `tools.Dispatch` 是无状态的、不持有 client。设计上通过 **context 注入** 把 LLM 处理函数传入（见 §3.5），避免在 `tools` 包反向依赖 `llm`/`runtime` 包造成循环依赖。

## 3. 详细设计

所有新工具的 handler 都加入 `Handlers` map，定义加入 `baseToolDefs`，并在 `defaultLocalAllowedTools` 中启用。参数校验由现有 `ValidateToolArgs` 自动覆盖。

### 3.1 `grep` — 文件内容正则搜索（纯 Go）

**参数**
| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pattern` | string | 是 | Go `regexp` 正则 |
| `path` | string | 否 | 搜索的文件或目录，默认 cwd |
| `glob` | string | 否 | 文件名过滤（如 `*.go`），用 `filepath.Match` 对 basename 匹配 |
| `output_mode` | string | 否 | `content` / `files_with_matches`(默认) / `count` |
| `-i` | bool | 否 | 忽略大小写 |
| `-n` | bool | 否 | content 模式显示行号 |
| `head_limit` | int | 否 | 限制输出条目数，默认 100 |

**实现要点**（新增 `internal/tools/search_ops.go`）
- 入口 `RunGrepFromRoot(root, workingDir, args)`；路径经 `resolvePathFromContext` 同源逻辑解析为绝对路径。
- 用 `regexp.Compile`（`-i` 时加 `(?i)` 前缀）；编译失败返回清晰错误。
- 目录递归用 `filepath.WalkDir`；自动跳过 `.git`、`node_modules`、`vendor` 等常见目录与疑似二进制文件（含 NUL 字节探测）。
- 单文件超大保护：复用 `maxReadLen` 量级上限，输出截断到 `maxOutputLen` 量级。
- `output_mode`：
  - `files_with_matches`：去重的文件路径列表；
  - `content`：`path:line:内容`（`-n` 控制行号）；
  - `count`：`path:匹配数`。
- 结果为空返回 `No matches found`。

### 3.2 `glob` — 文件名模式匹配

**参数**
| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pattern` | string | 是 | glob 模式，支持 `**`（递归）与 `*` |
| `path` | string | 否 | 搜索根目录，默认 cwd |

**实现要点**
- 复用 `resolvePathFromContext` 解析并约束 `path`。
- 用 `filepath.WalkDir` 遍历，配合 `doublestar` 语义的轻量实现：将 `**` 转换为递归匹配，其余段用 `path.Match`。为避免新增依赖，自实现 `matchGlob(pattern, relPath)`（仅支持 `**`、`*`、`?`、`[...]`，足够覆盖常见用法）。
- 返回按 **修改时间倒序** 的匹配文件路径（与 cn/tools/glob.md 描述一致）。
- 超过 `head_limit`（默认 100）截断并提示。

### 3.3 `ls` — 目录列举

**参数**
| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `path` | string | 是 | 要列出的**绝对路径** |
| `ignore` | string[] | 否 | 要忽略的 glob 模式数组 |

**实现要点**
- 需求规定 `path` 必须为绝对路径：非绝对路径返回错误提示。
- 仍须经 `safety.SafePathFromRoot(workspaceRoot, path)` 约束在 workspace 内（保持沙箱一致性）。
- 列出一层目录项；目录追加 `/` 后缀；命中任一 `ignore` 模式（对 basename 用 `matchGlob`）的项跳过。
- 输出为排序后的名称列表。

### 3.4 `multi_edit` — 单文件多次查找替换

**参数**
| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file_path` | string | 是 | 要修改文件的**绝对路径** |
| `edits` | object[] | 是 | 编辑数组，每项 `{old_string, new_string, replace_all?}` |

**实现要点**（新增 `RunMultiEditFromRoot`，复用 edit 语义）
- 路径校验复用 `resolvePathFromContext`。
- **原子性**：先读入文件内容到内存，按顺序对内存字符串依次应用每个 edit；任一 edit 失败（`old_string` 未找到、或 `old_string == new_string`）则整体放弃、不写盘、返回错误。全部成功后一次性写回。
- `replace_all=false`（默认）替换首个匹配；`true` 替换全部。
- 与现有 `edit_file` 行为对齐：`old_string` 必须精确匹配（含空白缩进）。
- 返回 `Applied N edits to <path>`。

> 复用策略：在 `file_ops.go` 增加 `RunMultiEditFromRoot`，内部不调用 `RunEditFromRoot`（避免多次读写），而是抽出共享的"内存内单次替换"小函数 `applyEdit(content, old, new, replaceAll)`。`edit_file` 现有行为保持不变。

### 3.5 `web_fetch` — 抓取并由 LLM 处理网页

**参数**
| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `url` | string | 是 | 完整 URL（http 自动升级 https） |
| `prompt` | string | 是 | 对网页内容要执行的处理指令 |

**实现要点**（新增 `internal/tools/web_ops.go`）
- 抓取：`http.Client`（带超时，受 `normalToolTimeout` 看门狗约束）；`http://` 升级为 `https://`；限制响应体大小（如 ≤ 2MB）。
- HTML → 文本：轻量清洗（去 `<script>/<style>`、去标签、解码实体、压缩空白）。不引入新依赖。
- LLM 处理：通过 context 注入的处理器执行。

**LLM 注入机制（避免循环依赖）**
- 在 `runtime_env.go` 新增：
  ```go
  type WebProcessor func(ctx context.Context, prompt, content string) (string, error)
  func WithWebProcessor(ctx, fn) context.Context
  func webProcessorFromContext(ctx) (WebProcessor, bool)
  ```
- 在 `tool_registry.go` 的 `Execute` 中，若 `Service` 持有 LLM，注入一个调用 `s.LLM.CreateChatCompletion` 的 `WebProcessor`（由 runtime 层装配，`tools` 包不依赖 `llm`/`runtime`）。
- 未注入处理器时：返回清洗后的纯文本（降级，不报错）。

### 3.6 `web_search` — 联网搜索（本期占位）

**参数**
| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `query` | string | 是 | 搜索查询 |
| `allowed_domains` | string[] | 否 | 仅包含这些域 |
| `blocked_domains` | string[] | 否 | 排除这些域 |

**实现要点**
- 注册完整定义（供模型识别），handler 在 **未配置搜索后端** 时返回：
  `web_search is not configured: no search backend available in this deployment.`
- 预留接入点：后续可通过 context 注入 `SearchProvider`，与 `web_fetch` 的注入模式一致。
- 该工具默认 **不** 加入 `defaultLocalAllowedTools`（避免暴露无效能力），仅保留定义；用户可在 config 显式启用。

## 5. 安全与边界

> 实施状态（2026-06-20 更新）：早期方案中的“workspace 沙箱越界一律拒绝”已被移除，路径越界保护改由
> 交互式审批机制承担（详见《终端命令权限审批机制设计文档.md》）。`safety.SafePathFromRoot` 现仅负责
> 路径解析与清理，不再拒绝工作区外的路径。

- **路径解析**：所有路径工具最终都经 `safety.SafePathFromRoot(workspaceRoot, …)` 解析为干净的绝对路径；写类操作（write/edit/multi_edit/bash 等）的越界风险由审批门控拦截，读类操作（read/grep/glob/ls）默认放行。
- **超时**：新工具均为非终端工具，自动受 `Dispatch` 的 60s 看门狗约束；`web_fetch` 内部 HTTP 另设更短超时。
- **资源上限**：grep/web_fetch 输出截断到现有 `maxOutputLen` 量级；web_fetch 响应体大小封顶。
- **二进制/忽略目录**：grep/glob 跳过 `.git`、`node_modules`、`vendor` 与二进制文件，避免噪音与性能问题。
- **无新增第三方依赖**：glob 匹配、HTML 清洗均自实现，保持 `go.mod` 不变。

## 6. 测试计划

- `grep`：正则匹配、`-i`、三种 output_mode、glob 过滤、空结果。
- `glob`：`**` 递归、`*` 单层、修改时间排序、head_limit。
- `ls`：绝对路径要求、ignore 模式、目录后缀。
- `multi_edit`：多 edit 顺序应用、原子失败回滚（不写盘）、replace_all、old==new 报错。
- `web_fetch`：用 `httptest.Server` 验证抓取+清洗；无 WebProcessor 时降级返回文本；有注入时走 mock 处理器。
- `web_search`：未配置后端返回占位提示。
- 定义层：`AllToolDefs` 含新工具；`defaultLocalAllowedTools` 解析后包含预期工具名。
- 全量 `go test ./...` 回归，确认现有工具行为不受影响。

## 7. 风险与权衡

- **glob/HTML 自实现 vs 引入库**：选择自实现以遵守"无新增依赖、surgical change"原则；代价是 glob 仅覆盖常见语法（`**`/`*`/`?`/`[...]`），复杂模式可能不支持——已满足需求文档示例。
- **web_search 占位**：避免暴露不可用能力，按用户决策本期不实现后端，仅预留注入点。
- **LLM 注入点**：通过 context 注入而非让 `tools` 包依赖 `llm`，保持包依赖方向不变，避免循环依赖。
